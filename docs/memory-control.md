# 结果感知的记忆控制层（v0，实验保留）

该层不是生产默认路径。无手写记忆、无预灌反馈的真实模型迁移评测中，原证据时态检索器以
更少步骤、读取和工具调用稳定胜出；因此 `mca tx run --memory local` 直接使用原检索器，控制层
只用于回归研究。在新的独立留出任务证明净收益前，不应重新接入默认链路。

记忆不应在“相似”时就一股脑塞进上下文。v0 控制层位于证据约束检索器之后，决定当前阶段是否
值得使用记忆、是否只给出反例警告、是否扩大查询，或者明确不用记忆。

```text
认证存储 → 作用域/时间/权限硬过滤 → 混合检索
                                     ↓
                阶段 + 历史结果 + token 成本 + 反记忆
                                     ↓
          retrieve / warning / requery / no_memory
```

## 已实现能力

- `MemoryControlContext` 描述 `start`、`working`、`stuck`、`pre_submit` 和
  `config_changed` 阶段，以及近期失败次数和 token 预算。
- 每个候选使用检索分数、带证据的成功/失败/有害反馈、阶段收益和 token 成本计算透明的
  期望效用；低于阈值的候选不会注入。
- `contraindication`、`counterexample` 和 `failure_pattern` 作为反记忆显式标注，渲染时不会
  伪装成普通建议。
- 没有合适记忆时返回 `no_memory`；Agent 已卡住且连续失败时返回 `requery`。
- 决策和结果均追加写入并使用 HMAC 认证。结果还必须绑定可信 Runtime 或用户证据；Agent
  自报“成功”不能训练策略。
- 影子模式记录如果采用该策略会选择什么，但永不渲染到上下文，其结果也不进入活跃效用统计。

控制层不能绕过底层的作用域、有效时间、来源、权限或证据门，也不能提高工具权限。

## 运行评测

```bash
.venv/bin/python -m evals.run_memory_control
.venv/bin/python -m evals.run_memory_intervention
.venv/bin/python -m pytest tests/test_memory_control.py tests/test_memory_control_eval.py -q
```

固定套件先证明静态检索会暴露一个已知有害候选，再验证控制层根据认证失败反馈将其抑制；同时
覆盖反例警告、无关查询克制、失败后重查和影子隔离。该套件完全离线、无模型调用，只证明这些
受控机制按定义工作，不证明开放环境泛化。

介入 A/B 进一步把建议上下文送入生产 `MiniCodeAgent`、工具执行器和验证门，并运行真实 fixture
单测。固定结果为：无记忆 5 步；静态召回 6 步、2 次编辑和 1 次编辑后失败；控制记忆 4 步、
1 次编辑且没有额外失败。三组最终都必须通过验证门才能提交。模型仍是会读取上下文的确定性
桩，因此该结果证明接线和保护机制，不代表真实模型的任务成功率提升。

## v0 边界与当前结论

当前期望效用是可审计的手工策略，并非训练出的 contextual bandit 或强化学习策略；一个决策
采用多条记忆时，结果暂时平均归因给所有选中项；尚未接入生产 Agent 上下文注入，也没有自动
探索。下一阶段应先用影子模式积累真实、可验证的反事实日志，再做离线策略评估和有限流量试验，
避免直接在线学习放大错误反馈。当前自然迁移的 3 次重复中，控制层平均 7 步、7 次读取和
14 次工具调用；原检索器为 6 步、4 次读取和 11 次工具调用。随后一次 27 调用复测再次得到
同样方向，因此现阶段结论是“保留机制、拒绝生产迁移”，不是继续围绕同一 holdout 调参。
