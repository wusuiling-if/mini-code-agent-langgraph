# v0.3.3 Sandbox Hardening Design

## Objective

Strengthen the command-isolation boundary that supports the project's
security-first positioning, and make the effective boundary independently
testable without a provider key or a real repository.

## Scope

This release will:

- hide host runtime control sockets and IPC from the Linux `bwrap` backend;
- stop granting macOS commands write access to shared host temporary trees;
- run Docker commands as the invoking POSIX user with a private, explicit
  container environment;
- provide `mca sandbox probe` for a disposable capability test;
- add opt-in real-backend integration tests and CI coverage;
- document backend-specific guarantees and remaining process-cleanup limits.

It will not add providers, a plugin framework, a TUI, a real-model benchmark,
or a broad executor refactor. Those changes have different risk and review
boundaries.

## Backend boundaries

### Bubblewrap

The host root remains read-only so interpreters and system libraries continue
to work. The backend will use `--unshare-all`, mount a private `/run`, a private
`/tmp`, a private home view, a private `/dev`, and a fresh `/proc`. Only the
workspace and the executor-owned runtime directory remain writable bind
mounts. This prevents path-based Unix sockets such as Docker and user D-Bus
from crossing the mount namespace.

### macOS sandbox-exec

The profile retains system read access required by interpreters and package
managers, denies network access, hides the real home directory except for a
workspace located under it, and denies writes by default. Write exceptions are
limited to the workspace and executor-owned runtime directory. Shared `/tmp`
and `/private/tmp` trees will no longer be writable.

### Docker

The container remains networkless, read-only, capability-free, PID/memory/CPU
limited, and bound to one writable workspace. On POSIX, it will run with the
host numeric UID:GID so generated files remain owned by the invoking user.
Container `HOME`, `TMPDIR`, Python bytecode, and Git configuration variables
will be set explicitly; `/tmp` remains a private size-limited tmpfs.

## Capability probe

`mca sandbox probe` creates a disposable directory containing a workspace and
a sibling protected file. It selects and launches the requested backend, then
checks:

1. a command can write inside the disposable workspace;
2. a command cannot overwrite the sibling protected file;
3. host Docker and user-bus socket paths are not visible;
4. an outbound socket connection is denied.

The command never opens a model-provider connection or touches the requested
project. Every check has a bounded timeout and prints a pass/fail result. A
missing interpreter needed for the network check is a failed capability test,
not a silent pass. `--sandbox none` is rejected because it cannot prove an
isolation boundary.

## Process cleanup

The existing process-group cleanup remains best effort for native backends;
it cannot prove that a double-forked process did not create a new session.
Bubblewrap's PID namespace and Docker's container boundary provide stronger
descendant containment. Documentation and probe output must not claim cgroup-
or container-equivalent cleanup for `sandbox-exec`.

## Testing

- Unit tests assert generated backend arguments and profile policy.
- Probe tests use a fake command runner to cover result aggregation and CLI
  exit behavior without requiring platform backends.
- Opt-in integration tests run the disposable probe against real
  `sandbox-exec`, `bwrap`, and Docker backends when explicitly enabled.
- CI installs or prepares each backend and runs its integration test.
- Existing 181 unit tests, the 11-case offline evaluation, package checks, and
  `mca demo` remain required release gates.

## Compatibility

The default `auto` order and explicit backend names remain unchanged. Docker
images must provide `/bin/sh` and `python3` for the capability probe; the
default `python:3.11-slim` image satisfies this contract. Normal coding runs
may still use a custom pre-pulled image without invoking the probe command.
