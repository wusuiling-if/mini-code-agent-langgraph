# v0.3.2 Trust and Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent false verification, remove the general CLI mock trap, publish an eleven-case offline policy benchmark, and harden the GitHub dependency/release path for v0.3.2.

**Architecture:** The executor owns authoritative test-command availability and recognized test-count evidence; the verification gate continues to consume only `ToolResult.returncode`. The CLI adds stricter capability selection, while the evaluation harness drives the existing production loop with scripted models and sanitized reports. Supply-chain controls remain isolated in GitHub configuration and workflow-policy tests.

**Tech Stack:** Python 3.10+, argparse, LangGraph/LangChain messages, pytest, unittest fixtures, GitHub Actions, Dependabot, CodeQL, pip-audit, GitHub rulesets.

## Global Constraints

- `mca run` requires explicit `--model` and `--test-command` and rejects CLI model `mock` with `mca demo` guidance.
- `mca chat` without `--test-command` remains useful in `/ask` but cannot enter or bypass `/code`.
- Recognized zero-test output fails closed unless the user explicitly passes `--allow-zero-tests`.
- Unknown custom test output continues to use its exit code; do not claim a generic test count.
- The benchmark is offline runtime-policy evidence, not model-quality or SWE-bench evidence.
- Benchmark artifacts contain only sanitized summaries, never trajectories, workspace contents, keys, Undo records, or journal paths.
- All third-party GitHub Actions remain pinned to reviewed full commit SHAs.
- Do not publish a package or create a release tag in this plan.
