> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Launch `mini-code-agent-langgraph 0.3.2` through a canonical GitHub feedback surface and one rules-compliant third-party community post, then capture a measurable baseline.

**Architecture:** Keep GitHub and PyPI as the canonical factual sources. Store reusable public copy in one tracked launch kit, use GitHub APIs for deterministic repository and Discussion changes, and use an authenticated browser only for UI-only actions or the single permitted Reddit post. Hacker News and V2EX remain human-only because their current rules prohibit generated or AI-edited text.

**Tech Stack:** Markdown, Git, GitHub CLI/REST/GraphQL APIs, GitHub Discussions, GitHub Releases, PyPI, in-app browser, Reddit.

- Never fabricate users, adoption, performance, security guarantees, or model-quality results.

- [ ] **Step 4: Create exactly one launch discussion**

Extract the body between `discussion-body:start` and `discussion-body:end`.
Resolve the exact title across every page before and after any create attempt so
the operation is resumable after an ambiguous response. With zero matches,
create once and query again; with one match, require the Announcements category,
update that same Discussion if its body differs, and read it back; with multiple
matches, stop without creating, updating, or deleting anything.

```bash
DISCUSSION_BODY="$(awk '/<!-- discussion-body:start -->/{inside=1;next}/<!-- discussion-body:end -->/{inside=0}inside' docs/launch/0.3.2.md)"
test -n "$DISCUSSION_BODY"
find_launch_discussions() {
  gh api graphql --paginate --slurp \
    -f query='query($owner:String!,$name:String!,$endCursor:String){repository(owner:$owner,name:$name){discussions(first:100,after:$endCursor){nodes{id title url body category{id}}pageInfo{hasNextPage endCursor}}}}' \
    -F owner=wusuiling-if \
    -F name=mini-code-agent-langgraph |
    jq '[.[].data.repository.discussions.nodes[] | select(.title == "mini-code-agent-langgraph 0.3.2: launch notes and technical feedback")]'
}
MATCHES_JSON="$(find_launch_discussions)"
MATCH_COUNT="$(printf '%s' "$MATCHES_JSON" | jq 'length')"
if [ "$MATCH_COUNT" -eq 0 ]; then
  gh api graphql \
    -f query='mutation($repositoryId:ID!,$categoryId:ID!,$title:String!,$body:String!){createDiscussion(input:{repositoryId:$repositoryId,categoryId:$categoryId,title:$title,body:$body}){discussion{id number url}}}' \
    -F repositoryId="$REPOSITORY_ID" \
    -F categoryId="$CATEGORY_ID" \
    -f title='mini-code-agent-langgraph 0.3.2: launch notes and technical feedback' \
    -f body="$DISCUSSION_BODY" >/dev/null
  MATCHES_JSON="$(find_launch_discussions)"
  MATCH_COUNT="$(printf '%s' "$MATCHES_JSON" | jq 'length')"
fi
test "$MATCH_COUNT" -eq 1
DISCUSSION_ID="$(printf '%s' "$MATCHES_JSON" | jq -r '.[0].id')"
DISCUSSION_URL="$(printf '%s' "$MATCHES_JSON" | jq -r '.[0].url')"
DISCUSSION_CATEGORY_ID="$(printf '%s' "$MATCHES_JSON" | jq -r '.[0].category.id')"
test "$DISCUSSION_CATEGORY_ID" = "$CATEGORY_ID"
REMOTE_DISCUSSION_BODY="$(printf '%s' "$MATCHES_JSON" | jq -r '.[0].body')"
if [ "$REMOTE_DISCUSSION_BODY" != "$DISCUSSION_BODY" ]; then
  gh api graphql \
    -f query='mutation($discussionId:ID!,$body:String!){updateDiscussion(input:{discussionId:$discussionId,body:$body}){discussion{id url}}}' \
    -F discussionId="$DISCUSSION_ID" \
    -f body="$DISCUSSION_BODY" >/dev/null
  MATCHES_JSON="$(find_launch_discussions)"
  test "$(printf '%s' "$MATCHES_JSON" | jq 'length')" -eq 1
  REMOTE_DISCUSSION_BODY="$(printf '%s' "$MATCHES_JSON" | jq -r '.[0].body')"
fi
test "$REMOTE_DISCUSSION_BODY" = "$DISCUSSION_BODY"
printf 'discussion_url=%s\n' "$DISCUSSION_URL"
```

Expected: exactly one matching Discussion is created or safely reused and, when
needed, the one verified Announcements Discussion is updated in place. Any
ambiguous create response is resolved by the full paginated title query; a
second create is never used as a retry.
